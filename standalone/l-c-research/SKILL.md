# Deep Research (картирование → поиск)

Глубокий ресёрч по **жёсткой процедуре**. Ключевой принцип: **сначала понимаем, КТО изучает проблему и каким источникам там доверяют — только потом ищем.** Не пропускай фазы и не запускай поиск до Фазы 5.

## Движок (hybrid)

- **Оркестрация — Claude-native:** ты ведёшь фазы, показываешь карту, ждёшь решений пользователя, запускаешь параллельные суб-исследования через субагентов (`Task`/`Agent`, `WebSearch`, `WebFetch`).
- **Тяжёлый дайвинг — опционально OpenAI Deep Research API:** для глубокого погружения по отдельному кластеру можно подключить внешний Deep Research (например, OpenAI o4-mini-deep-research). Предлагай это, когда кластер большой и пользователь хочет максимальную глубину.

## Процедура — 6 фаз с воротами

Между крупными фазами **показывай результат и жди «OK»** (Фаза 1, 2, 3-4 — это ворота). Не беги вперёд.

### Фаза 0 — Рамка проблемы
Заполни ТЗ (спрашивай только недостающее, одним блоком):

| Поле | Значение |
|---|---|
| Главный вопрос | … |
| Дисциплина / контекст | … |
| Тип ответа (данные / обзор / сравнение / рекомендации / критика) | … |
| Временной коридор | … (уточним в Фазе 4) |
| География / культура | … |
| Глубина (дайджест / глубокий анализ) | … |
| Практическое применение | … |

Кратко пересказать задачу своими словами для подтверждения.

### Фаза 1 — Карта кластеров (ядро подхода)
Подробности и эвристики: [cluster-discovery.md](references/cluster-discovery.md).

1. **Науки** — какие дисциплины изучают эту проблему (всегда, даже если тема прикладная).
2. **Индустрии** — для каких индустрий проблема важна и **кто в них её изучает**. Это обязательный шаг: местами экспертиза индустрии > академии (геймдев, реклама, трейдинг, UX). Науки смотрим всегда; индустрии добавляем поверх.
3. **Методики** — в каждом кластере: какими подходами/методами там работают с этой проблематикой.
4. **Ключевые слова** — собрать термины + синонимы по кластерам (с учётом, что в разных доменах одно явление называется по-разному).

**Ворота 1:** показать пользователю карту кластеров (таблица: кластер | тип наука/индустрия | кто именно | методики | ключевые слова). Ждать реакции.

### Фаза 2 — Выбор режима
- **A. Обзорный** — параллельный обзор по всем кластерам сразу.
- **B. Выборочный** — пользователь называет кластеры → независимые исследования (параллельные субагенты).
- **C. Цепочкой** — одно исследование на основании результатов другого (реже, дороже).
- **D. UPDATE / temporal-diff** — перезапуск прежнего ресёрча с поклеймовым диффом «что изменилось». См. [report-format.md](references/report-format.md).

**Ворота 2:** спросить режим и (для B/C) порядок/выбор кластеров.

### Фаза 3 — Калибровка доверия к источникам (по кластеру)
Подробности и профили доменов: [source-profiles.md](references/source-profiles.md).

Для каждого выбранного кластера определить **его собственные** требования к источникам: чему он доверяет, что считает актуальным и надёжным.
- Академия: peer-review, Q-квартиль, цитируемость, DOI, мета-анализы/Cochrane.
- Индустрия: профильные конференции (напр. GDC), постмортемы, отчёты ведущих студий/лабораторий, практики с именем, бенчмарки.

Из этих принципов собрать **список источников на кластер** + **рубрику качества на кластер**.

### Фаза 4 — Временные диапазоны
Спросить у пользователя коридор по каждому кластеру, **предложив дефолт**: где лежат самые свежие релевантные данные (в одних областях фронтир — последние 1-2 года, в других классика 20-летней давности всё ещё канон). Эвристики — в [source-profiles.md](references/source-profiles.md).

**Ворота 3-4:** показать собранный план поиска (кластеры × источники × критерии качества × ключевые слова × диапазоны). Ждать «OK».

### Фаза 5 — Запуск поиска
Только теперь. Для каждого кластера (в режиме B/A — параллельные субагенты):
1. **Снять верхние слои:** найти обзоры/мета-анализы за период → тренды, лакуны, ключевые авторы.
2. **Дайвинг:** по подвопросам достать первоисточники, прогнать через quality-gate кластера.
3. **Итеративное доискивание:** если после отсева источников меньше нужного или ключевой клейм спорный (низкая уверенность) — расширить (новые ключевые слова, базы, годы) и повторить. См. [quality-gates.md](references/quality-gates.md).

### Фаза 6 — Синтез и проверка
Полный формат — [report-format.md](references/report-format.md), проверки — [quality-gates.md](references/quality-gates.md).
1. Сводные таблицы по кластерам (источник, год, выборка/контекст, метод, выводы, лимиты).
2. Кросс-кластерные противоречия — выявить и объяснить причины.
3. **Adversarial-проход:** CRITIC ищет противоречия/предвзятость, FACT-CHECKER верифицирует ключевые числа.
4. Финальный отчёт: TL;DR → таблица данных → доказательная база с кликабельными DOI → ограничения → что дальше.

## Доп. практики (включены)
- **Adversarial CRITIC + FACT-CHECKER** — отдельный скептический проход перед выдачей.
- **Hypothesis-driven + iterative deepening** — авто-доискивание спорных клеймов до набора качества.
- **UPDATE / temporal-diff** — режим D, поклеймовый дифф с прошлым ресёрчем.
- **Decisions ledger + source cards** — журнал «почему включён/исключён источник» + карточки источников для воспроизводимости.

## Тон и частые fails
Тон: профессионально-скептичный, без хайпа. Не путать новизну с качеством; не цитировать новости вместо peer-review; не верить слепо числу цитирований; не путать корреляцию с причинностью; не утаивать методологические дыры. Полный список — [quality-gates.md](references/quality-gates.md).

# Report Format — выдача и UPDATE-режим

## Пошаговая доставка

Показывать результат **по завершении каждого крупного шага** (карта кластеров → план поиска → результаты по кластеру → синтез); ждать «OK» перед переходом. В финале — единый markdown-отчёт.

## Структура финального отчёта

1. **TL;DR** — 3 строки для нетерпеливых.
2. **Таблица ключевых данных** — сводный DataFrame: источник, год, выборка/контекст, метод, вывод, лимиты, кластер.
3. **Доказательная база** — разбор по кластерам/тезисам; для каждого тезиса: утверждение → доказательства (с кликабельными DOI/URL) → уровень достоверности → оговорки.
4. **Ограничения / спорные места** — противоречия между источниками и кластерами + объяснение причин; что осталось неясным.
5. **Что делать дальше** — практические импликации и куда копать.

Приложения: source cards (по ключевым источникам), decisions ledger.

DOI давать кликабельными ссылками. Тон — профессионально-скептичный.

## Режим B (выборочный, параллельный)

Каждый кластер — независимый суб-отчёт (субагент), затем общий синтез-слой с кросс-кластерными противоречиями. Не смешивать критерии качества разных кластеров при оценке внутри кластера; смешивать только на уровне синтеза.

## Режим C (цепочкой)

Результат кластера N питает запрос к кластеру N+1 (новые ключевые слова/гипотезы из находок). Фиксировать в ledger, что именно перенесено.

## Режим D — UPDATE / temporal-diff

Перезапуск прежнего ресёрча для проверки «что изменилось».
1. Взять прошлый отчёт как baseline (список клеймов с источниками и уровнями достоверности).
2. Повторить поиск с тем же планом, но суженным временным коридором (с момента baseline).
3. **Поклеймовый дифф** — таблица:

| Клейм | Было | Стало | Статус |
|---|---|---|---|

Статусы: `подтверждён` / `усилен` / `ослаблен` / `опровергнут` / `новый` / `устарел`.
4. Обновить decisions ledger: что нового включено, что отозвано.

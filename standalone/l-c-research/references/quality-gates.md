# Quality Gates — отсев, доискивание, проверка

## Чек-лист оценки источника (академический кластер)

| Критерий | Вопрос | Мин. требование |
|---|---|---|
| Журнал | Q-квартиль? | ≤ Q2 |
| Цитируемость/год | Выше медианы по полю? | Да |
| Методы | Рандомизация, слепой контроль, power-анализ? | В наличии (если применимо) |
| Данные | Открыты и воспроизводимы? | Да |
| Конфликты интересов | Указаны? | Да |
| Финансирование | Нет единственного спонсора с прямой выгодой? | Да |
| Ретракты | В Retraction Watch? | Нет |

**Для клинических тем:** обязательно искать RCT / обзоры Cochrane.

## Чек-лист для индустриального кластера

| Критерий | Вопрос |
|---|---|
| Авторитет | Команда/автор с подтверждённым треком в домене? |
| Воспроизводимость | Бенчмарк/кейс можно повторить, есть данные/метод? |
| Свежесть | Соответствует фронтиру кластера? |
| Независимость | Не реклама собственного продукта без данных? |
| Первоисточник | Это сам доклад/постмортем, а не пересказ? |

## Итеративное доискивание (hypothesis-driven)

1. Прогнать найденное через чек-лист кластера.
2. Не прошедшее — пометить «низкое качество» или исключить (с записью в ledger, см. ниже).
3. Если после отсева источников меньше нужного **или** ключевой клейм спорный (низкая уверенность, противоречивые данные) → расширить поиск (новые ключевые слова, доп. базы, более ранние годы) и повторить цикл.
4. Продолжать, пока выборка не укомплектована качественными источниками и спорные клеймы не разрешены или явно помечены как нерешённые.

## Adversarial-проход (перед выдачей)

- **CRITIC:** отдельным проходом (можно субагентом) ищет противоречия между источниками, предвзятость отбора, необоснованные обобщения, подмену корреляции причинностью.
- **FACT-CHECKER:** верифицирует ключевые числовые утверждения по первоисточникам; каждое важное число должно иметь прослеживаемый источник.

## Source cards (карточка источника)

На каждый ключевой источник:
```
- id / автор / год
- кластер
- тип (мета-анализ / RCT / постмортем / бенчмарк / …)
- выборка или контекст
- метод
- главный вывод
- лимиты
- уровень доверия (high / medium / low) + почему
- DOI / URL
```

## Decisions ledger (журнал решений)

Лог для воспроизводимости: каждое включение/исключение источника и каждое расширение поиска — строкой: `что → решение → почему`. Прикладывать к финальному отчёту.

## Частые fails (избегать)

- Путать новизну с качеством: свежие статьи нужны для трендов, но до независимой репликации — предварительные.
- Цитировать новостные сайты вместо peer-review/первоисточника.
- Слепо верить числу цитирований (популярный фейк тоже цитируем).
- Путать корреляцию с причинностью.
- Утаивать методологические дыры «для простоты».

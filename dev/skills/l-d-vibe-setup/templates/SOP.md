# Vibe-Coding SOP для дизайнеров JetStyle

**Версия:** 1.0 | **Обновлено:** 14 марта 2026
**Источник:** EdDesign lessons learned + исследование vibe-design-solutions.md

---

## Для кого

Дизайнеры JetStyle, делающие сайты через Claude Code / Cursor.

## Принципы

1. **Ты не рисуешь — ты менеджеришь AI-разработчика.** Твоя задача — ставить задачу и проверять результат
2. **Спека ДО кода, всегда.** 2 дня на документацию экономят 3 недели переделок
3. **Одна задача = один диалог.** `/clear` между задачами
4. **CMS решается до кодинга, не в процессе.** Claude не выбирает CMS

## Фазы проекта

### Фаза 1: Дизайн (Figma, 1-2 дня)

- Wireframes в Figma
- Design tokens: цвета, отступы, типографика
- Компоненты с правильными именами (Button, Hero, Footer — не Group 42)
- Адаптив: мобайл (375px), планшет (768px), десктоп (1280px)
- Тегирование компонентов в Figma для MCP

### Фаза 2: Спека (0.5 дня)

Три документа в корне проекта:

| Документ | Что содержит |
|----------|-------------|
| `requirements.md` | Страницы, фичи, интерактивность, кто пользователь |
| `design-decisions.md` | Стек, CMS (или No CMS), хостинг, сторонние сервисы |
| `tasks.md` | Упорядоченный список задач на реализацию (1 задача = 1 сессия Claude) |

Ревью с лидом перед началом кодинга.

Для генерации спеки: `/sdd-spec-init`, `/sdd-spec-requirements`, `/sdd-spec-design`, `/sdd-spec-tasks`.

### Фаза 3: Скаффолд (2 часа)

1. Скопировать CLAUDE.md из шаблона (`10-CLAUDE/vibe-coding-claude-md-template.md`)
2. Заполнить поля: клиент, тип, CMS
3. Инициализировать Next.js + Tailwind + shadcn
4. Подключить Figma MCP (если есть Org-план)
5. Сгенерировать структуру страниц по спеке

### Фаза 4: Реализация (1-3 дня)

- Одна задача на сессию из `tasks.md`
- `/clear` между задачами
- Playwright-скриншоты после каждой страницы
- `/security-reviewer` после форм и авторизации
- Коммит после каждой завершённой задачи

### Фаза 5: Приёмка (0.5 дня)

- [ ] Playwright — полные скриншоты vs Figma
- [ ] `/owasp-security` — сканирование уязвимостей
- [ ] Lighthouse — performance > 90
- [ ] Кросс-браузерное тестирование (Chrome, Safari, Firefox)
- [ ] Респонсив на реальных устройствах

---

## Чеклист гигиены сессий

- [ ] `/clear` перед новой задачей
- [ ] Субагенты для исследований (не загрязнять контекст)
- [ ] `/compact` если контекст тяжёлый, но задача продолжается
- [ ] Коммит после каждой завершённой задачи
- [ ] Максимум 50 ходов в сессии, потом новая
- [ ] Не работать в одном длинном диалоге весь день

## CMS-стратегия по типу проекта

| Тип проекта | CMS | Почему |
|---|---|---|
| Лендинг, промо-сайт | **No CMS** (markdown/JSON) | Ноль инфраструктурных багов |
| Корпсайт с редким обновлением | **No CMS** или **Sanity** | Клиент редактирует 1-2 раза/мес |
| Контентный сайт (журнал, блог) | **Sanity** или **WordPress** | Sanity = лучший UX; WP = если ведёт Женя |
| Приложение с данными | **Supabase** / **PostgreSQL** | CMS не нужна, нужна БД |

---

## Что НЕ делать

1. Не давать Claude выбирать CMS
2. Не использовать кастомный CSS (только Tailwind utility-классы)
3. Не работать в одном длинном диалоге
4. Не хардкодить ключи и секреты
5. Не использовать CMS, встроенную во фреймворк (Payload-in-Next.js)
6. Не пропускать спеку ("быстрее сразу кодить" — нет, медленнее)
7. Не использовать первые мажорные релизы CMS в клиентских проектах

## Стек

```
Framework:    Next.js 15 (App Router)
Styling:      Tailwind CSS v4 + shadcn/ui
CMS:          По проекту (см. таблицу выше)
Auth:         NextAuth / Clerk
Hosting:      Vercel
AI:           Claude Code (complex) + v0 (UI) + Lovable (quick MVP)
Testing:      Playwright MCP (visual) + Vitest (unit)
Security:     /owasp-security + /security-reviewer
```

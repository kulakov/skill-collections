## Команда: new-project <name>

Создай новый проект по шаблону:

1. Создай папку `10-CLAUDE/<name>/`
2. Прочитай `templates/CLAUDE.md (в этой папке)`
3. Создай `CLAUDE.md` из шаблона, спроси пользователя: клиент, тип проекта, CMS
4. Файлы requirements.md / design-decisions.md / tasks.md создавай ТОЛЬКО если есть чем их наполнить прямо сейчас (см. глобальное правило скилла); иначе просто упомяни их в CLAUDE.md как «появятся при необходимости»
5. Спроси: "Инициализировать Next.js + Tailwind + shadcn? (y/n)"
6. Если да -- выполни scaffold:
   ```bash
   npx create-next-app@latest <name> --typescript --tailwind --eslint --app --src-dir
   cd <name> && npx shadcn@latest init -d
   ```

## Глобальное правило скилла: не плодить пустоту

НЕ создавай папок и файлов «на вырост» — под то, чего в проекте ещё нет (пустые requirements.md, tasks.md, src/ без кода). Единственное исключение: можно создать папку, если она нужна, чтобы положить CLAUDE.md в правильное место (корень проекта). Всё остальное — только когда появится содержимое.

## Команда: interview (режим «правила под контекст»)

Последовательное интервью → CLAUDE.md, построенный под конкретный проект. Не шаблон, а правила из фактов.

Правила ведения: вопросы строго ПО ОДНОМУ; у каждого вопроса — норма хорошего ответа (1-2 предложения); расплывчатый ответ — переспроси (challenge, как в l-nic Interview-режиме); не предлагай содержание за пользователя.

Вопросы (пропускай те, ответ на которые уже виден из контекста/репо — но проговори, что увидел, для подтверждения):

1. **Что за проект и стадия?** Норма: одно предложение сути + стадия (идея / прототип / код есть / прод живой)
2. **Где живёт код?** Путь, есть ли git, есть ли уже структура папок. Если репо существует — посмотри его сам (ls, README) и подтверди увиденное
3. **Стек и почему.** Норма: язык/фреймворки + причина выбора (или «унаследовано»)
4. **Кто работает в репо?** Только Claude / человек+Claude / несколько людей. От этого зависит тон правил (для агентов — ловушки и запреты; для людей — конвенции)
5. **Источники истины.** Какие документы уже существуют (спека, архитектура, контракты) и что из них — закон. НЕ предлагай создавать недостающие — только фиксируй существующие
6. **Жёсткие запреты.** Что в проекте делать НЕЛЬЗЯ (секреты, зависимости, стили, деплой без спроса...)
7. **Известные ловушки.** Что уже ломалось / неочевидно (окружение, сборка, кэши, песочницы)
8. **Workflow.** Тесты перед коммитом? журнал прогресса? одна задача за сессию? что должно происходить в конце сессии

После интервью:
1. Собери черновик CLAUDE.md: только секции, под которые есть реальные ответы (пустых разделов-заглушек не делать). Структура-ориентир: Что это → Источники истины → Структура (только СУЩЕСТВУЮЩИЕ папки) → Жёсткие правила → Ловушки окружения → Workflow
2. Покажи черновик пользователю целиком, спроси что поправить
3. После подтверждения запиши в корень проекта (создай только эту папку, если её нет). Ничего другого не создавай

## Команда: cms-decision

Покажи CMS Decision Tree:

| Тип проекта | CMS | Почему |
|---|---|---|
| Лендинг, промо | **No CMS** (markdown/JSON) | Ноль багов |
| Корпсайт | **No CMS** или **Sanity** | Редкие обновления |
| Контентный сайт | **Sanity** или **WordPress** | Sanity = UX, WP = Женя |
| Приложение | **Supabase** / **PostgreSQL** | CMS не нужна |

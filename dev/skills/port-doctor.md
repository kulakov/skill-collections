# Port Doctor — Управление сервисами

Скрипт: `~/lance-claude/10-CLAUDE/port-doctor/port-doctor.sh`
Реестр: `~/lance-claude/10-CLAUDE/port-doctor/ports.json`
Состояние: `~/lance-claude/10-CLAUDE/port-doctor/state.json`

## Команды

Пользователь вызывает `/port-doctor [команда] [сервис]`:

| Аргумент | Действие |
|----------|----------|
| (пусто) или `status` | Показать статус всех сервисов |
| `on <service>` | Включить + запустить + запомнить |
| `off <service>` | Выключить + остановить + запомнить |
| `start` | Запустить все enabled |
| `stop` | Остановить все |
| `ports` | Карта портов |
| `conflicts` | Найти конфликты |

## Выполнение

1. Разбери аргументы из `$ARGUMENTS`: первое слово = команда, второе = сервис
2. Запусти `port-doctor.sh` с нужными аргументами
3. Покажи результат пользователю

```bash
~/lance-claude/10-CLAUDE/port-doctor/port-doctor.sh $ARGUMENTS
```

Если пользователь просит "включи X" или "запусти X" — используй `on X`.
Если "выключи X" или "останови X" — используй `off X`.
Если просто спрашивает что работает — используй `status`.

## Правила реестра (обязательно)

1. **ports.json — единственный source of truth по портам.** Новый сервис с портом → сначала запись в реестр, потом запуск. Выделение порта: следующий свободный из **8091-8199** (см. секцию `allocation`; `never_use`: 3000, 8080).
2. **Смена/выдача порта → синк с порталом:** обновить `~/all-projects/services.json` (секция internal: `domain`, `url`, `check.url`) и передеплоить: `cd ~/all-projects && node build-index.js && vercel deploy --prod --yes`. Статусы и кнопки на портале обслуживает отдельный демон — он читает services.json, рестарт не нужен.
3. **Проверка фактического состояния:** `lsof -iTCP:<port> -sTCP:LISTEN` — реестр может врать; при расхождении чинить реестр, не реальность (если реальность осмысленна — как pubtopdf на 8090).
4. Порты второго сервера — зона его собственного вотчдога, этим скриптом не управляются; фиксировать в реестре информационно.

# Transcript Router

Автоматически определи тип транскрипта и примени подходящий скилл.

## Алгоритм классификации

Прочитай первые 500 слов транскрипта и определи:

### 1. Тип встречи

| Маркеры | Тип | Скилл |
|---------|-----|-------|
| "клиент", "бюджет", "проект", "КП", "предложение", "сроки", "стоимость", обсуждение цен, scope работ | **Клиентский созвон** | `/l-t-call-analysis` |
| "боль", "проблема", "как сейчас решаете", "что не устраивает", "как часто", "готовы ли платить", customer discovery | **Проблемное интервью** | `/l-t-problem-interview` |
| стратегическое обсуждение, много участников, сложные темы, требуется граф связей | **Глубокий анализ** | `/thesis-extraction` |
| внутренняя встреча, синхрон, статус, планирование, ретро | **Простой конспект** | `/l-t-transcript` |
| лекция, подкаст, длинный монолог, образовательный контент | **Большой конспект** | `/l-c-big-summary` |

### 2. Сигналы для выбора

**l-t-call-analysis** — когда важно:
- Оценить перспективы сделки
- Понять что клиент хочет между строк
- Выделить возможности для upsell
- Определить следующие шаги продаж

**l-t-problem-interview** — когда важно:
- Валидировать гипотезу о проблеме
- Понять Jobs To Be Done
- Оценить интенсивность боли
- Проверить готовность платить

**thesis-extraction** — когда важно:
- Извлечь ВСЕ тезисы и позиции
- Построить карту аргументов
- Увидеть связи между идеями
- Разобрать сложную дискуссию

**l-t-transcript** — когда нужно:
- Быстро понять о чем говорили
- Выделить решения и action items
- Простой формат без излишеств

**l-c-big-summary** — когда:
- Это не диалог, а монолог/лекция
- Текст очень длинный (>10000 слов)
- Нужен подробный конспект

## Процесс работы

1. **Прочитай транскрипт** (файл или текст)

2. **Выведи классификацию:**

```
## Анализ транскрипта

**Обнаруженные маркеры:**
- [перечисли 3-5 ключевых маркеров]

**Определенный тип:** [тип встречи]

**Рекомендуемый скилл:** `/skill-name`

**Почему:** [1-2 предложения обоснования]
```

3. **Спроси подтверждение:**
> Применить `/skill-name` к этому транскрипту?
> Или выбери другой: /l-t-transcript | /l-t-call-analysis | /l-t-problem-interview | /thesis-extraction | /l-c-big-summary

4. **После подтверждения** — вызови выбранный скилл с транскриптом

## Обработка неопределенности

Если маркеры противоречивы:
1. Предложи 2 варианта с объяснением
2. Дай пользователю выбрать

Если транскрипт короткий (<500 слов):
- По умолчанию `/l-t-transcript`

## Пример

**Input:** Транскрипт звонка где обсуждается "их текущее решение", "что не устраивает", "готовы ли попробовать"

**Output:**
```
## Анализ транскрипта

**Обнаруженные маркеры:**
- "как сейчас решаете" — discovery вопрос
- "что не устраивает" — исследование боли
- "готовы ли" — проверка готовности

**Определенный тип:** Проблемное интервью

**Рекомендуемый скилл:** `/l-t-problem-interview`

**Почему:** Разговор фокусируется на выявлении проблем и текущих решений респондента — классический customer discovery.
```

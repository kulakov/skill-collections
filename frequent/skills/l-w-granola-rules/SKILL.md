# Granola Rules — управление правилами диспетчеризации

Единая линза и редактор над таблицей правил `ROUTING.md`. Чтобы не искать правила по проектам руками
и не терять целостность.

## Данные (источник истины)
- **`~/00-INBOX/_granola/ROUTING.md`** — таблица правил + карта участников.
- Скил только читает/правит этот файл и сверяет ссылки с файловой системой. Никакой второй копии правил.

## Команды

### list — «какие правила настроены»
Прочитай ROUTING.md, выведи правила компактной таблицей: `# · паттерн · 2-й сигнал · обработчик · режим`.
Добавь сводку: сколько AUTO / AUTO·safe / ASK / SKIP.

### filter — «какие правила в этом проекте X» / «правила синхронизации <команда>»
Покажи только правила, чей обработчик/цель касаются X (по имени команды, рецепта или папки-цели).
Если X — трекер-команда, покажи и путь её STATE/DIARY.

### lookup — «какой обработчик у <событие>» / «чем разбирается этот созвон»
Сопоставь заголовок события с паттернами (регистронезависимо, по подстроке; для группы сервис отчётности —
по карте участников) и назови обработчик + режим. Если матча нет → скажи «fallback: ASK».

### set — «измени правило <паттерн> на <обработчик>» / «переведи <паттерн> в auto|ask|skip» / «добавь правило»
1. Найди строку в ROUTING.md (или добавь новую с следующим #).
2. Поменяй колонку Обработчик и/или Режим.
3. **Сразу прогони check** (см. ниже) — правка не считается принятой, пока обработчик не резолвится.
4. Покажи дифф (было → стало) и результат проверки.

### check — «проверь целостность правил»
Запусти `references/check.sh` и проинтерпретируй вывод. Проверяется:
- `track debrief <team>` → существует `11-TRACKER/teams/<team>/STATE.md`
- `рецепт NN-name` → существует `09-REFERENCE/my-promts/granola-recipes/NN-name.md`
- скил-обработчик (`l-w-redaktor`, `l-g-call`, `insight-distill` …) → есть в `~/.claude/skills` или `commands`
- режим ∈ {AUTO, AUTO·safe, ASK, SKIP}
- нет двух правил с одинаковым паттерном (дубль) и осиротевших целей
Выведи: ✓ OK по каждому или список проблем с конкретикой (что и где не найдено).

## Правила работы
- Всегда показывай дифф при правке, не молча.
- При любой правке — авто-check, и если что-то красное — предупреди до сохранения.
- Файлы с кириллицей в пути — полный абсолютный путь; ASCII — markdown-ссылка.
- Эмодзи не используй (✓/⚠/× — ок).
